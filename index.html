What this post-read covers

Why pattern matching needs its own mini-language; re.search() and re.match(); metacharacters; character classes and shorthands (\d, \w, \s); quantifiers; re.findall(); capturing groups; and a cumulative log-parsing mini project.

01 · the idea

Plain string methods run out of road fast

Suppose we're reading a support inbox and want to pull out every message that contains a phone number. With plain string methods, the best we can do is check for a dash:

message = "Call me at 555-1234 or email support@example.com"

has_dash = "-" in message
print(has_dash)
🔮 Before you reveal: this only tells us there's a dash somewhere. What starts to go wrong if we try to check for a phone number, an email, and a date, all with plain string methods like this?

There's no way to say "three digits, then a dash, then four digits." No way to handle phone numbers written slightly differently. No reusable way to describe a shape rather than exact text. What we really want is a way to describe the shape of what we're looking for — "some digits, then a dash, then some more digits" — instead of one exact piece of text. That's exactly what a regular expression, or regex, gives us.

✅ TakeawayRegex lets you describe the shape of text you're looking for, instead of matching one exact string at a time.
02 · what is a regex

A small language of its own

A regular expression is a small, separate language for describing patterns in text. It's not Python syntax — it's a pattern string that Python's re module reads and applies for us. Every regex program starts the same way:

import re
Term Meaning
Pattern The regex string describing what to look for.
Literal A character in the pattern that just matches itself (like c matching c).
Metacharacter A character with special meaning (like . or *).
Match object What re returns when it finds a hit.
📌 NoteAlways write patterns as raw strings, with an r in front — r"..." — so backslashes in the pattern aren't accidentally interpreted by Python itself before regex ever sees them.
03 · re.search()

Finding a pattern anywhere

re.search() looks through the whole string for the first place the pattern matches, no matter where it appears. If it finds one, it gives back a Match object. If not, it gives back None.

🔮 Predict: will this print something, or will it print None? 
text = "concatenate"
result = re.search(r"cat", text)
print(result)

<re.Match object; span=(3, 6), match='cat'>

re.search() found 'cat' hiding inside 'concatenate', starting at index 3. The Match object tells you both that it matched and exactly where.

📌 NoteA common beginner mistake is treating the Match object like a boolean in unusual ways — it's truthy when a match is found and None (falsy) when it isn't, which is why if re.search(...): works cleanly as a check.
04 · re.match()

Anchored at the start

re.match() looks almost identical to re.search(), but with one important difference: it only checks the very beginning of the string. If the pattern doesn't show up right at the start, match() gives up immediately — even if the pattern exists later in the string.

🔮 Both lines search for the same pattern in the same string — will both find a match, or only one? 
text = "concatenate"

print(re.match(r"cat", text))
print(re.search(r"cat", text))

None
<re.Match object; span=(3, 6), match='cat'>

re.match() failed because 'concatenate' doesn't start with 'cat' — it starts with 'con'. re.search() succeeded because it's allowed to look anywhere in the string.

✅ TakeawayUse match() when the pattern must be at the very start (like validating a string begins with a country code), and search() when the pattern can be anywhere.
05 · metacharacters

The building blocks

A metacharacter is a character in a pattern that means something special, instead of matching itself literally:

Symbol Meaning
. Any single character (except a newline).
^ Start of the string.
$ End of the string.
* Zero or more of the previous thing.
+ One or more of the previous thing.
? Zero or one of the previous thing.
{} An exact number, or range, of repeats.
[] A character class — any one character from a set.
\ Escape the next character, or start a shorthand class.
| OR — match one pattern or another.
() A capturing group.
🔮 Predict which of these words the pattern will match, if any 
pattern = r"c.t"

for word in ["cat", "cot", "ct", "coat"]:
    print(word, bool(re.search(pattern, word)))

cat True
cot True
ct False
coat False

The . matched any single character between c and t — so 'cat' and 'cot' both worked, since exactly one character sits in that middle spot. 'ct' failed because there's nothing between c and t at all, and 'coat' failed because . only stands for one character, not two.

📌 NoteIf you actually want to match a literal dot — like in a filename report.pdf — you have to escape it: r"\.". An un-escaped . in a pattern almost never means what a beginner expects.
06 · character classes

Matching one character from a set

A character class lets us say "match any one character from this specific set" using square brackets — and because some sets come up constantly, regex gives us shorthand for them too:

Pattern Matches
[abc] Any one of a, b, or c.
[a-z] Any lowercase letter.
[0-9] Any digit (same idea as \d).
[^0-9] Anything that is NOT a digit (^ inside [] means negation).
\d Any digit — shorthand for [0-9].
\w Any word character — shorthand for [a-zA-Z0-9_].
\s Any whitespace — space, tab, newline.
\D \W \S The negation of each of the above.
🔮 Predict True or False for each line 
print(bool(re.search(r"[aeiou]", "sky")))
print(bool(re.search(r"\d", "Room 42")))
print(bool(re.search(r"^\w+$", "hello world")))

False
True
False

'sky' has no vowels at all, so the first check correctly fails. 'Room 42' contains a digit, so \d matches. The last one is the interesting one: \w does not include the space character, so 'hello world' — which has a space in the middle — does not fully match ^\w+$ from start to end.

🤖 AI momentIf you're unsure why an underscore counts as a "word" character, ask an AI assistant: "Why does \w in regex include the underscore character, but not a space or a hyphen? Give me a couple of real examples where that distinction matters." Then independently verify: write a pattern using \W (capital) that matches only non-word characters, and confirm it matches spaces and punctuation but not letters, digits, or underscores.
07 · quantifiers — the vote

How many times can this repeat?

A quantifier says how many times the thing right before it is allowed to repeat:

Symbol Meaning
* Zero or more.
+ One or more.
? Zero or one (optional).
{3} Exactly 3.
{2,4} Between 2 and 4 (inclusive).
{2,} 2 or more, no upper limit.

Which of these phone numbers will match \d{3}-\d{4}?

pattern = r"\d{3}-\d{4}"

for number in ["555-1234", "55-1234", "555-12345", "5551234"]:
    print(number, bool(re.fullmatch(pattern, number)))

555-1234 True
55-1234 False
555-12345 False
5551234 False

{3} and {4} demand an exact count — not "roughly," exactly. '55-1234' has only two digits before the dash, and '555-12345' has five digits after it, so both fail. '5551234' has no dash at all, so it fails too.

📌 Notere.fullmatch() is like search(), but it requires the entire string to match the pattern from end to end — useful whenever you're validating an entire piece of input, like a form field, rather than just checking if a pattern shows up somewhere inside it.
08 · re.findall()

Getting every match, not just the first

search() and match() only ever give us the first match. But often we want every match in a string — every phone number in a document, every hashtag in a tweet. That's what re.findall() is for.

🔮 Predict what this prints before running it 
text = "Reach us at 555-1234 or 555-9876, but not after 5pm."
numbers = re.findall(r"\d{3}-\d{4}", text)
print(numbers)

['555-1234', '555-9876']

findall() scans the whole string and returns every non-overlapping match as a list. '5pm' didn't get pulled in, since it doesn't have the shape \d{3}-\d{4} at all.

📌 NoteIf the pattern contains capturing groups, findall() changes behavior and returns the group contents instead of the whole match — see the next card.
09 · capturing groups

Pulling out just the piece you want

Right now, when we match something, we only get the whole match back — the entire phone number, the entire email. But usually we want a specific piece of it. Parentheses in a pattern create a capturing group, which lets us pull out just that piece.

🔮 Predict: what will group(0), group(1), and group(2) each return? 
text = "Name: Rex, Age: 3"
match = re.search(r"Name: (\w+), Age: (\d+)", text)

print(match.group(0))
print(match.group(1))
print(match.group(2))

Name: Rex, Age: 3
Rex
3

group(0) (or just group()) always returns the entire match, exactly like without any groups at all. group(1) and group(2) return only what fell inside the first and second sets of parentheses, in order.

✅ TakeawayThe pattern describes the whole shape of the text, but the groups tell Python exactly which pieces you actually want to keep.
10 · findall() with groups

A genuinely surprising behavior change

🔮 findall() with groups behaves differently than findall() without them — predict what this returns 
text = "Name: Rex, Age: 3; Name: Fido, Age: 5"
pairs = re.findall(r"Name: (\w+), Age: (\d+)", text)
print(pairs)

[('Rex', '3'), ('Fido', '5')]

When a pattern has groups, findall() no longer returns the whole matches — it returns a list of tuples, one tuple per match, holding just the captured groups in order. This is genuinely surprising the first time you see it, so it's worth testing directly rather than assuming.

🤖 AI momentAsk an AI assistant: "Show me how to rewrite the pattern r'Name: (\w+), Age: (\d+)' using named groups instead of numbered groups, and how I would read match.group('name') afterward." It should show you the (?P<name>...) syntax and match.groupdict(). Then independently verify: rewrite the Name/Age pattern using (?P<name>\w+) and (?P<age>\d+), and confirm match.group('name') and match.group('age') return the same values group(1) and group(2) did.
✅ TakeawayNumbered groups work fine for a quick pattern, but named groups are usually worth the extra typing once a pattern has more than two or three groups.
11 · mini project

Extracting data from log lines

Combine every idea from this class into one small, realistic program: a list of raw server log lines, each with a timestamp, a log level, and a message — pulled apart with character classes, quantifiers, and capturing groups.

🔮 Predict all three lines of output — what timestamp, level, and message will print for each log line? 
import re

logs = [
    "2024-03-01 08:15:02 ERROR Failed to connect to database",
    "2024-03-01 08:15:05 INFO Retry succeeded",
    "2024-03-01 08:16:40 WARNING Disk usage above 90%",
]

pattern = r"(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) (\w+) (.+)"

for line in logs:
    match = re.match(pattern, line)
    timestamp, level, message = match.groups()
    print(f"[{level}] {timestamp} — {message}")

[ERROR] 2024-03-01 08:15:02 — Failed to connect to database
[INFO] 2024-03-01 08:15:05 — Retry succeeded
[WARNING] 2024-03-01 08:16:40 — Disk usage above 90%

This program uses every core idea from this class: character classes and quantifiers to shape the timestamp (\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}), \w+ to grab the log level as one word, .+ to grab the rest of the line as the message, and three capturing groups pulled apart at once with match.groups().

✅ Takeawayre.match() was enough here, not search() — every log line genuinely starts with its timestamp, so anchoring at the start is exactly the right tool.
12 · final recap

The one idea to leave with

PATTERN (the "shape") │ ┌──────────────┼──────────────┐ ↓ ↓ ↓ metachars classes quantifiers .^$ \d \w \s + ? {} │ │ │ └──────────────┴──────────────┘ ↓ search() / match() / findall() ↓ capturing groups (pull out just what you need)

A regex is a separate mini-language for describing the shape of text, not the exact text itself. re.search() finds a pattern anywhere in a string; re.match() only counts a match at the very start. Metacharacters like . ^ $ * + ? give individual characters special meaning, and character classes like [a-z] or shorthands like \d, \w, \s describe a whole set of characters at once. Quantifiers control how many times something repeats. re.findall() pulls out every match at once, and capturing groups let you extract specific pieces of a match — with findall() returning tuples of just the captured groups whenever a pattern has them.

✅ TakeawayPredict what a pattern will match before running it — regex punishes assumptions faster than almost anything else in this course.
